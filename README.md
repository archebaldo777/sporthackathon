# Драфт — платформа ИТ-найма с верифицированным профилем участника ФСП

**Обратная механика найма:** кандидат один раз проходит опрос и адаптивный тест и попадает в категорию
«специализация × грейд». Работодатель описывает потребность, получает объяснимую подборку из подходящих
категорий и **сам приглашает конкретного человека** — с описанием предложения, зарплатной вилкой и способом связи.
Контакты кандидата раскрываются только после того, как он принял приглашение.

Решение для задачи «Цифровая платформа-агрегатор ИТ-вакансий с верифицированным профилем достижений участника
Федерации спортивного программирования» (ФСП, 2026).

| | |
|---|---|
| Кандидату | опрос → выбор грейда → адаптивный тест → категория → приглашения с вилкой; несколько категорий (основная и до двух дополнительных, грейд в каждой — тестом); PDF-резюме с автораспознаванием; PDF-профиль с QR-проверкой; связь с ФСП ID; регулярные задачи; отклики на вакансии; переписка с работодателем и отзыв доступа к контактам; регистрация с 15 лет |
| Работодателю | потребность текстом (NLP) → рекомендованные категории → ранжированная подборка с «почему в подборке» → приглашение; уточнение без потери подборки; банк кандидатов и карта категорий; вакансии и отклики; задачи для кандидатов с проверкой на списывание; синхронизация с ATS (вакансии, отклики, статусы — API и вебхуки); переписка с кандидатом после принятия приглашения |
| Механика тестирования | 226 шаблонов-генераторов заданий (ответ вычисляется), IRT 3PL + адаптивный тест (CAT) с контентной балансировкой и контролем экспозиции, онлайн-калибровка и детекция дрейфа |
| Механика подбора | категории из теста, а не резюме; интерпретируемая формула из 6 компонент с «гейтом» по обязательным навыкам; сила доказательства навыка (тест > ФСП > задача > резюме); актуальность дисциплины ФСП для специализации; смежные категории; вероятность принятия приглашения |
| Интеграция с ФСП | ФСП ID по OIDC (Authorization Code + PKCE, совместимо с Keycloak), реестр достижений, корректная работа без истории ФСП |
| Фирменный стиль ФСП | цвета, шрифты (JetBrains Mono, TDAText), официальный логотип, гибридные паттерны и цветовой код дисциплин из брендбука ФСП — в интерфейсе, письмах, PDF-профиле и документации ([п. 1.4](docs/01-architecture.md)) |

## Результаты валидации (кратко)

Подробно — [docs/04-validation.md](docs/04-validation.md) и страница `/validation` в приложении.

| Что проверяли | Результат |
|---|---|
| Подбор: nDCG@10 на 217 потребностях (5 независимых наборов) | **0.79 ± 0.02** против 0.54 у поиска по резюме и 0.68 у самоописанной категории |
| Подбор: P@5 / P@10 / MRR | **0.85** / 0.72 / 0.98 (классика: 0.59 / 0.52 / 0.78); лучше классики в **99%** запросов |
| Подбор: веса формулы | подобраны на отдельных наборах потребностей в продуктовых рамках, проверены на независимых: nDCG@10 0.772 → 0.793 |
| Тест: грейд совпадает с истинным | 81% (самоописание — 74%), ±1 грейд — 100%, вдали от порогов — 90%, взвешенная κ = 0.90; в среднем 14.8 задания |
| Тест: завышенный в анкете грейд | **не подтверждается в 85%** случаев; честно заявленный подтверждается в 82% |
| Тест: повторное прохождение (другая форма) | r(θ̂) = 0.88, взвешенная κ грейда = 0.86, совпадение решения 86% |
| Дискриминативность | AUC соседних грейдов 0.92–0.94, медиана точечно-бисериальной корреляции 0.53 |
| Атака утечкой ответов | статичный банк: Junior проходит Middle в 97%; «Драфт» не выдаёт уже показанный вариант — **из утечки 0% заданий, проходит 5%** (как без утечки — 7%) |
| Контрольная форма при сигналах нечестности | у честных кандидатов срабатывает в 0.6% случаев; грейд подтверждается короткой формой из свежих заданий |
| Разбор резюме (40 резюме, размечены вручную) | отложенный набор, первый замер: специализация 94%, ФИО 94%, контакты 100%, навыки F1 0.94 |
| Ключи ответов заданий с кодом | 918 сгенерированных вариантов исполнены настоящими компиляторами 9 языков и SQLite — **918 совпали с ключом** |

**Проверка на своём наборе пар.** Механику подбора можно прогнать на любом размеченном наборе «вакансия — кандидат»
(тексты вакансий и резюме или поля, оценки 0–3 или 0/1): страница `/validation` → «Загрузить JSON», API
`POST /api/v1/validation/external-eval` или консоль. Формат и пример — [docs/examples/eval_pairs_example.json](docs/examples/eval_pairs_example.json);
на примере (8 специализаций, 47 вакансий, 620 кандидатов) nDCG@10 0.75 против 0.58 у поиска по резюме.

```bash
cd backend && .venv/bin/python -m app.validation.external_eval ../docs/examples/eval_pairs_example.json
docker compose cp pairs.json backend:/tmp/pairs.json && docker compose exec backend python -m app.validation.external_eval /tmp/pairs.json
```

## Быстрый старт (Docker)

Требуется Docker 24+ с Compose v2, ~1 ГБ свободной памяти.

```bash
docker compose up --build
```

| Адрес | Что это |
|---|---|
| http://localhost:8080 | веб-приложение |
| http://localhost:8080/api/docs | Swagger UI (OpenAPI) |
| http://localhost:8025 | Mailpit — письма подтверждения e-mail |
| http://localhost:8081 | демо-стенд ФСП ID (Keycloak-совместимый OIDC) и реестр достижений |

При первом запуске backend создаёт схему БД и синтетические данные (~720 кандидатов, 15 компаний) — около 10 секунд.

**Демо-стенд:** https://sporthackathon.ru (ФСП ID — https://fsp.sporthackathon.ru, демо-почта — https://mail.sporthackathon.ru).

**Публичный стенд** на любом сервере с Docker — одной командой, с HTTPS и без покупки домена (адреса `*.sslip.io`):
`./deploy/deploy.sh` — подробно в [docs/08-deployment.md](docs/08-deployment.md).

**Демо-видео:** [docs/demo/draft-demo.mp4](docs/demo/draft-demo.mp4) — 4 минуты 20 секунд, сквозные сценарии обеих ролей:
опрос и адаптивный тест, приглашение и переписка, несколько категорий, «Рост и зарплаты», подборка, сравнение кандидатов,
интеграция с ATS, режим эксперта для жюри, валидация, вход через ФСП ID (записано автоматически сценарием `docs/demo_video.py`).
Организаторы допускают видео вместо живого стенда.

### Демо-аккаунты (пароль `Demo2026!`)

| E-mail | Роль |
|---|---|
| `employer@draft.demo` | работодатель «ТехноВектор»: потребности, подборки, приглашения |
| `candidate@draft.demo` | кандидат Backend · Middle с достижениями ФСП и приглашениями |
| `candidate2@draft.demo` | кандидат Frontend · Junior без истории ФСП |
| `newbie@draft.demo` | новый кандидат: пройти опрос и тест с нуля |
| `expert1@draft.demo` … `expert5@draft.demo` | новые кандидаты для жюри с **режимом эксперта**: пройти тест самому или за минуту — синтетическим профилем заданного уровня |

**Режим эксперта** (только демо-стенд, только `expertN` и `newbie`): на странице теста кнопки «Ответить верно / неверно» и
«Пройти как профиль уровня θ» (стажёр … senior, в том числе «на пороге» грейда) — ответы генерируются по модели IRT, ключи
остаются на сервере. Так за 1–3 минуты проверяется разделяющая сила (разные уровни → разные грейды) и воспроизводимость
(тот же уровень в другом аккаунте → тот же грейд на других заданиях). Те же прогоны массово — на странице «Валидация».

Демо-спортсмены ФСП ID: логины показаны на странице входа ФСП ID, пароль `fsp2026`.

## Локальный запуск без Docker

Нужны Python 3.12+ (проверено на 3.13), Node.js 20+, PostgreSQL 14+.

```bash
createdb draft
cd backend && python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
.venv/bin/uvicorn app.main:app --port 8000 --reload
```

```bash
cd fsp-mock && ../backend/.venv/bin/pip install -r requirements.txt && ../backend/.venv/bin/uvicorn app.main:app --port 8081
```

```bash
cd frontend && npm install && npm run dev
```

Приложение: http://localhost:5173. Без SMTP-сервера код подтверждения e-mail выводится в лог backend.
Подробности и переменные окружения — [docs/08-deployment.md](docs/08-deployment.md).

## Проверки

```bash
cd backend && .venv/bin/python -m pytest -q
```

```bash
cd frontend && npm test
```

```bash
cd frontend && npx playwright test   # нужен запущенный стенд: по умолчанию http://localhost:5173, иначе E2E_BASE_URL
```

```bash
cd backend && .venv/bin/python -m app.validation.run_all
```

Бэкенд — 278 автотестов (pytest), фронтенд — 14 тестов компонентов (Vitest) и 7 браузерных сценариев (Playwright): банк заданий (каждый шаблон, ключ согласован с вариантом), IRT/CAT, NLP, свойства ранжирования,
сквозные API-сценарии (регистрация с подтверждением, тест, категория, подборка, приглашение, раскрытие контактов,
ограничения доступа и частоты смены грейда, повышение отдельным тестом, бесплатный шаг вниз, неподтверждённый грейд в выдаче,
переписка и отзыв доступа к контактам, регистрация 15–17 лет, режим эксперта), сверка ключей ответов исполнением кода. Валидация пишет отчёт в `backend/validation_results/`.

```bash
cd backend && .venv/bin/python -m app.validation.code_exec --docker   # ключи ответов: 9 языков в Docker-образах компиляторов
```

CI (`.github/workflows/ci.yml`): автотесты с компиляторами всех языков, сборка фронтенда, запуск в Docker и сквозная проверка API.

## Структура репозитория

```
backend/            FastAPI: API, бизнес-логика, механики тестирования и подбора, NLP, валидация, тесты
  app/api/v1/       HTTP-слой (роутеры, RBAC)
  app/testing/      банк шаблонов-генераторов, IRT, CAT, сервис попыток
  app/matching/     ранжирование, объяснения, подборки, сила профиля
  app/nlp/          разбор резюме и потребностей
  app/fsp/          клиент ФСП ID (OIDC) и оценка достижений
  app/services/     приглашения, задачи, антифрод, вебхуки, PDF, почта, согласия
  app/seed/         синтетические данные
  app/validation/   процедура валидации (Монте-Карло, метрики подбора, разбор резюме, проверка на своём наборе пар)
fsp-mock/           демо-стенд ФСП ID (Keycloak-совместимый OIDC) + реестр достижений
frontend/           React + TypeScript + Vite + Tailwind: кабинеты кандидата и работодателя
docs/               сопроводительная документация, openapi.json, демо-видео и сценарий его записи
deploy/             публичный стенд: Caddy (HTTPS), наложение compose, deploy.sh
docker-compose.yml  PostgreSQL, Mailpit, fsp-mock, backend, frontend (nginx)
```
