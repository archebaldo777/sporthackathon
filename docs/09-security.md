# 9. Безопасность и 152-ФЗ

## 9.1. Персональные данные (Федеральный закон № 152-ФЗ)

| Требование | Реализация |
|---|---|
| Согласие на обработку ПДн | обязательный чекбокс при регистрации (сервер отклоняет регистрацию без него) |
| Отдельное согласие на публикацию профиля | кандидат управляет видимостью в базе; отзыв согласия скрывает профиль из поиска и подборок |
| Согласие на получение данных из реестра ФСП | фиксируется при связывании ФСП ID, отзыв удаляет полученные достижения |
| Журнал согласий | таблица `consents`: вид, версия документа, решение, дата, IP, User-Agent; виден кандидату в настройках |
| Минимизация раскрытия | работодатель до принятия приглашения видит код кандидата вместо имени и не видит контактов; текущий работодатель скрыт; кандидат может скрыть зарплатные ожидания, ФСП, результаты задач |
| Право на доступ | выгрузка всех своих данных в JSON (`GET /candidate/export`) |
| Право на удаление | удаление аккаунта со всеми связанными данными (`DELETE /candidate/account`, каскадное удаление) |
| Аудит | `audit_log`: раскрытие контактов, просмотры профиля работодателем, выгрузки, связывание ФСП ID, удаления |
| Отзыв доступа к контактам | после принятия приглашения кандидат может закрыть контакты: они исчезают из кабинета, API и ATS-выгрузки работодателя; действие пишется в аудит |
| Несовершеннолетние (15–17 лет) | регистрация только с согласием законного представителя (запись в журнале согласий); работодатель видит пометку и ограничения ТК РФ |
| Шифрование в БД | ФИО, телефон и Telegram кандидата хранятся зашифрованными (AES-256-GCM, случайный nonce, имя поля как AAD; ключ `FIELD_ENCRYPTION_KEY` или производный от `SECRET_KEY`) — дамп базы не раскрывает контакты |
| Хранение | PostgreSQL в контуре оператора; в продакшене — размещение в РФ, шифрование дисков и резервных копий |

* Секреты не попадают в репозиторий: `.env`, ключи JWT и тестовые ключи — в `.gitignore`; CI проверяет всю историю
  репозитория сканером **gitleaks**.

## 9.2. Аутентификация и сессии

* Регистрация по e-mail с подтверждением: 6-значный код (хранится только SHA-256-хеш) или одноразовая ссылка, срок 24 часа.
* Пароли — **Argon2id** (параметры OWASP: m = 19 МиБ, t = 2), требования к сложности на сервере.
* Access-токен JWT **RS256**, 30 минут, Keycloak-совместимые claims; публичный ключ в JWKS.
* Refresh-токен — случайный 320-бит, в БД хранится хеш; **ротация** при каждом обновлении, отзыв при выходе.
* Защита от перебора: 5 неудачных входов → блокировка на 5 минут; rate limiting чувствительных эндпоинтов (20 запросов/мин с IP).
* Вход через ФСП ID: Authorization Code + **PKCE S256**, проверка `state` (≤ 10 мин), `nonce`, подписи `id_token` по JWKS,
  `iss` и `aud`; автоматического связывания по совпадению e-mail нет (защита от захвата аккаунта).

## 9.3. Разграничение прав

* Роли `candidate`, `employer`, `admin` в `realm_access.roles`; зависимости `require_role` на каждом роутере.
* Кабинеты доступны только с подтверждённым e-mail.
* Объектный уровень: каждый запрос к приглашению, отклику, потребности, вакансии, задаче проверяет владельца
  (чужой объект → 404, без раскрытия факта существования). Проверено автотестами.
* ATS-доступ — отдельные API-ключи (хранится хеш, префикс для поиска), отзыв в один клик.

## 9.4. Сетевой периметр и OIDC

* На публичном стенде наружу открыты только 80/443 (Caddy, TLS); база, API, мок ФСП ID и почта — во внутренней сети.
* Реальный IP клиента за прокси берётся из `X-Forwarded-For` (`uvicorn --proxy-headers --forwarded-allow-ips`), поэтому
  лимиты частоты входа и регистрации считаются на пользователя, а не на прокси.
* Демо-стенд ФСП ID, как и Keycloak, принимает только зарегистрированные адреса возврата (`FSP_ALLOWED_REDIRECTS`):
  код авторизации не может уйти на чужой домен (открытый редирект закрыт, проверяется и подмена префиксом).

## 9.5. Защита тестирования

Ключи ответов не покидают сервер; время ответа считается по серверным часам; одно активное задание на попытку (защита от
повторной отправки), лимиты попыток; сигналы нечестности (уходы со вкладки, вставки, сверхбыстрые ответы, person-fit) — см. п. 2.6.

## 9.6. Прочее

* Заголовки безопасности: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy`.
* CORS — только для адресов фронтенда.
* Валидация всех входных данных Pydantic-схемами (длины, диапазоны, форматы, ИНН); загрузка резюме — только PDF до 5 МБ.
* Подпись PDF-профиля (HMAC) и QR-проверка подлинности; подпись вебхуков HMAC-SHA256.
* Контейнеры запускаются от непривилегированного пользователя.
